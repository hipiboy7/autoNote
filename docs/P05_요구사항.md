# 📋 Phase 5 요구사항 정의서: 주간리뷰(Weekly Review) 생성 엔진 개발

이 문서는 투자 리서치 수집 하이브리드 배치 프로그램의 다섯 번째 단계인 **주간리뷰(Weekly Review) 생성 및 기록 모듈**에 대한 비즈니스 및 기능적 요구사항을 정의합니다.

---

## 1. 개요 및 비즈니스 목적
*   **목적:** 매주 토요일 배치 실행 시점에 최근 7일 동안 수집/기록된 분석 내용과 사용자 생각을 종합하여, 심도 깊은 주간 성찰 및 지식 요약 보고서(Weekly Review)를 생성하고 `40_리뷰 YYYY-Wxx` 구글 Docs에 기록한다.
*   **해결하려는 문제:** 정보가 매일 단편적으로 축적되다 보면 큰 흐름(반도체 사이클, 매크로 뷰 등)의 변화를 놓치기 쉽습니다. AI 추론 모델을 활용해 주간 단위로 저자의 관점 변화와 사용자의 생각을 일괄 점검하여 입체적인 학습 효과를 제공한다.

---

## 2. 기능적 요구사항 (Functional Requirements)

### 2.1 주간 리뷰 트리거 조건
*   배치 실행일의 요일이 **토요일**인 경우에만 주간리뷰 생성 프로세스를 자동으로 시작한다.
*   (수동 명령인 `주간리뷰` 명령어가 들어온 경우 요일과 상관없이 즉시 재생성을 기동한다.)

### 2.2 리뷰용 데이터 수집 및 전처리
*   최근 7일 동안 신규 추가된 테마/종목 구글 Docs 내의 분석 레코드 블록들을 식별자와 날짜를 기반으로 긁어모은다.
*   **취합할 원천 데이터:**
    *   날짜, 제목, 핵심 주장, 판단 논리, 리스크 요소
    *   사용자가 해당 블록에 기록한 `▶ 💭 내 생각` 코멘트 내용
    *   해당 블록의 `▶ ❓ 생각해볼 질문` 내용

### 2.3 AI 기반 주간 리뷰 요약 생성 규칙 (`reasoning-llm`)
*   취합된 7일간의 지식 맵을 입력으로 삼아, 고도의 논리적 추론 모델(`reasoning-llm`)에 다음 4대 서식 규격에 맞춘 요약서 작성을 의뢰한다.
*   **주간리뷰 필수 작성 서식:**
    1.  **이번 주 핵심 논리 3가지:** 
        *   "저자는 [근거]를 보고 [논리]로 [판단]했다" 형식의 깔끔한 한 문장 요약과 이를 뒷받침하는 상세 부연. (반드시 원문 날짜 인용 예: `07-12 글`)
    2.  **과거 기록 대비 저자의 관점 변화:**
        *   최근 7일간의 코멘트를 과거 축적된 성향과 비교하여 저자의 생각이나 톤(매수 강도, 낙관론/비관론 수치 등)이 변했는지 분석.
        *   형식: `[이전 관점] ➔ [현재 관점]` 형태로 핵심 기술 (변화가 포착되지 않은 경우 `변화 없음` 명시, 인용 날짜 기재).
    3.  **사용자 생각(💭) 점검 및 대조:**
        *   사용자가 적은 💭 코멘트들을 종합 검토하여 저자의 생각과 일치한 부분과 불일치(혹은 의문이 남는 부분)한 부분을 대조 성찰.
        *   이전 글들에서 제시되었던 질문(❓)에 대해 이번 주 새로 수집된 글들이 답을 주었는지 확인하여 매칭.
        *   생각노트 💭를 비워둔 채 넘어간 항목이 많다면 기록을 부드럽게 권장하는 문구 포함.
    4.  **다음 주 관찰 포인트 3가지:**
        *   이번 주 논리를 검증하거나 모니터링해야 할 핵심 매크로 지표, 이벤트, 또는 기업 가설 3가지 도출.

### 2.4 주간 리뷰 구글 Docs 기록 및 포맷
*   문서 명명 규칙: `40_리뷰 YYYY-Wxx` (예: `40_리뷰 2026-W29`)
*   가독성을 위해 세피아 크림색 배경색(`#FDF6E3`)을 동일하게 일괄 적용한다.
*   매주 새 문서를 생성하거나 기존 동일 주차 문서의 내용을 갱신(Overwrite)한다.

## 3. 비기능적 요구사항 (Non-Functional Requirements)

### 3.1 추론 품질 관리
*   원문에 존재하지 않는 무근본 예측이나 모델의 허구 전망(Hallucination)이 섞이지 않도록, 모든 주장 뒤에는 반드시 근거가 되는 **글의 날짜**를 대괄호 인용(`[MM-DD]`)하도록 프롬프트 레벨에서 엄격히 제한한다.
*   주식 매수/매도 권유 등 금융 투자 추천으로 보일 수 있는 직접적인 투자 판단 문구 생성을 철저히 배제한다.

### 3.2 테스트 가용성 (Testability)
*   주간 데이터 조회 및 프롬프트 주입 로직을 mock 환경에서 철저히 검증한다.
*   리뷰 텍스트 파싱, 주차(Wxx) 계산, AI 리포트 렌더링, 구글 Docs 저장 조율 기능의 코드 커버리지 95% 이상을 달성한다.

---

## 4. 제약 사항 (Constraints)
*   일주일간 추가된 신규 리서치 메시지가 1건도 없는 경우, 주간리뷰 작성을 스킵하고 "이번 주 추가된 리서치가 없어 주간리뷰를 생성하지 않습니다." 경고 로그를 남긴다.
