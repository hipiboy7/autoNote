# 📋 Phase 4 요구사항 정의서: 생각노트 자동 병합(Merge) 개발

이 문서는 투자 리서치 수집 하이브리드 배치 프로그램의 네 번째 단계인 **생각노트 코멘트 자동 역병합(Merge) 모듈**에 대한 비즈니스 및 기능적 요구사항을 정의합니다.

---

## 1. 개요 및 비즈니스 목적
*   **목적:** 사용자가 `99_생각노트` 구글 문서에 직접 기록해둔 생각 코멘트를 자동으로 파싱하고, 이를 해당 고유 식별자가 존재하는 본문 테마/종목 Docs의 `▶ 💭 내 생각:` 자리에 병합 업데이트(치환)한다.
*   **해결하려는 문제:** 매번 사용자가 요약 문서를 읽고 수동으로 의견을 복사-붙여넣기 하던 번거로움을 자동화하여 지식 축적 생산성을 극대화한다.

---

## 2. 기능적 요구사항 (Functional Requirements)

### 2.1 생각노트 파싱 및 코멘트 추출
*   **대상 문서:** `99_생각노트` 구글 문서
*   **파싱 패턴:**
    *   대소문자 구분 없이(case-insensitive), 식별자 접두사 패턴 `\[(t|s|f|r)(\d+)\]`을 찾아 매칭한다. (예: `[t305]`, `[T305]`, `[s1024]` 등 모두 대응)
    *   해당 식별자 아래 라인의 `▶ 💭 내 생각: (사용자 입력 코멘트)` 패턴에서 실질적으로 사용자가 타이핑해둔 텍스트 코멘트를 안전하게 추출한다.
*   **건너뜀 조건:**
    *   코멘트 텍스트가 비어 있거나, 기본값인 `미기록` 또는 공백만 있는 경우는 병합 대상에서 제외한다.

### 2.2 본문 Docs 검색 및 자동 치환 (Merge)
*   **대상 문서:** 식별자 알파벳에 따라 매핑된 테마/종목/프레임 구글 Docs
*   **병합 동작:**
    1.  대상 구글 Docs의 전체 텍스트를 읽어온다.
    2.  문서 내에서 일치하는 식별자(예: `[t305]`) 레코드 블록을 찾아낸다.
    3.  해당 블록 하단의 `▶ 💭 내 생각: 미기록` 라인을 찾아 `▶ 💭 내 생각: {추출된 사용자 코멘트}`로 안전하게 교체(Update)한다.
    4.  이미 사용자의 생각이 기록되어 있는 상태에서 사용자가 생각노트의 코멘트를 수정했다면, 새로운 내용으로 덮어써서 업데이트(Overwrite) 반영한다.

### 2.3 생각노트 정리 (Clean up)
*   성공적으로 본문 Docs에 치환 병합된 코멘트는 `99_생각노트` 문서 내에서 `[처리완료]` 상태로 수정하거나 삭제하여, 다음 배치 시 중복 병합 작업이 일어나지 않도록 클린업 처리를 보장해야 한다.

---

## 3. 비기능적 요구사항 (Non-Functional Requirements)

### 3.1 텍스트 치환 정확성
*   엉뚱한 식별자의 `▶ 💭 내 생각:` 라인이 침범되어 덮어써지지 않도록, **반드시 매칭된 식별자 블록의 바운더리(Boundary) 내에서만** 치환 작업을 수행해야 한다.
*   구글 Docs의 `replaceText` API나 구글 Docs 텍스트 인덱스를 활용하여 정확한 범위 내에서의 치환을 수치적으로 보장해야 한다.

### 3.2 테스트 가용성 (Testability)
*   실제 구글 Docs API 호출 없이 가상의 전체 텍스트 상태에서 생각 코멘트 추출 및 본문 치환 로직이 견고하게 도는지 `MockGoogleDocsClient`를 통해 검증한다.
*   생각노트 파싱, 대소문자 혼용 매칭, 본문 블록 치환, 클린업 처리 로직의 코드 커버리지 95% 이상을 달성한다.

---

## 4. 제약 사항 (Constraints)
*   본문 치환 도중 예외가 발생하더라도 전체 배치 파이프라인이 중단되어서는 안 되며, 에러 로그를 남기고 다음 메시지 병합으로 안전하게 넘어가야 한다.
