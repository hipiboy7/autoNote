# 📋 Phase 2 요구사항 정의서: LLM 분석 Gateway 개발

이 문서는 투자 리서치 수집 하이브리드 배치 프로그램의 두 번째 단계인 **LLM 분석 Gateway 및 프롬프트 분석 엔진**에 대한 요구사항을 정의합니다.

---

## 1. 개요 및 비즈니스 목적
*   **목적:** 수집된 텔레그램 메시지 원문을 읽고, 이를 정교한 투자 리서치 지식(핵심 주장, 근거, 판단 논리, 리스크, 생각해볼 질문)으로 정제하여 구조화된 JSON 데이터로 반환한다.
*   **해결하려는 문제:** 기존 에이전트의 들쭉날쭉한 프롬프트 응답 형식을 탈피하고, 운영 환경과 테스트 환경 간의 매끄러운 AI 백엔드 교체를 지원하는 추상화 인터페이스를 제공한다.

---

## 2. 기능적 요구사항 (Functional Requirements)

### 2.1 LLM 추상화 모델 및 명명 표준
*   시스템 코드는 백엔드 기술 스펙에 강결합되지 않도록 **Generic Alias**만 참조한다.
*   **alias 매핑 요구사항:**
    *   `chat-llm`: 일반 채팅/리서치 분류/주석 작성용
        *   *Production:* vLLM Qwen3-Coder 30B
        *   *Test:* OpenAI gpt-4o
    *   `reasoning-llm`: 고도의 추론 및 논리적 분석용
        *   *Production:* vLLM GPT-OSS 130B
        *   *Test:* OpenAI o4-mini
    *   `embedding`: 지식 임베딩용
        *   *Production:* bge-m3 ONNX
        *   *Test:* OpenAI text-embedding-3-small

### 2.2 표준 환경변수 주입
*   각 alias는 아래 환경변수를 통해서만 세팅 정보를 주입받아 초기화된다 (하드코딩 금지).
    *   `CHAT_LLM_BASE_URL` / `_MODEL` / `_API_KEY`
    *   `REASONING_LLM_BASE_URL` / `_MODEL` / `_API_KEY`
    *   `EMBEDDING_BASE_URL` / `_MODEL` / `_API_KEY` / `_DIM`
    *   `OPENAI_API_KEY` (테스트 환경 전용 API Key 주입용)

### 2.3 투자 리서치 핵심 논리 분석 (프롬프트 엔진)
*   **입력:** 텔레그램 메시지 원문
*   **추출 대상 필드:**
    1.  **핵심 주장 (Main Claim):** 저자가 이 글을 통해 최종적으로 전달하고자 하는 결론 (1~2문장으로 한글 요약).
    2.  **근거 및 데이터 (Evidence & Data):** 핵심 주장을 뒷받침하기 위해 본문에서 제시된 구체적인 수치, 관찰 데이터, 사실(Fact) 목록.
    3.  **판단 논리 (Logic):** ★가장 중요★ 저자가 어떤 매크로/미크로 지표나 프레임워크를 기반으로 왜 그러한 해석을 내렸는지에 대한 추론 경로 분석.
    4.  **리스크 및 반대 시나리오 (Risks):** 저자가 본문에서 언급한 잠재 위험 요소 및 원문에 없더라도 사용자가 점검해 보아야 할 구조적 리스크 제시.
    5.  **생각해볼 질문 (Critical Question):** 이 리서치 글의 논리나 가설을 검증하기 위해 사용자가 후속 연구해 보아야 할 핵심 질문 1개.

### 2.4 구조화된 응답 보장 (Structured Outputs)
*   분석 엔진은 무조건 **JSON 규격**으로 최종 분석 결과를 출력해야 한다.
*   Pydantic 데이터 검증(Schema validation)을 통과하지 못하는 비정상적인 JSON 형식이 생성된 경우, 분석 프로세스는 즉각 실패하고 최대 2회 재시도(Retry with correction)를 진행해야 한다.

---

## 3. 비기능적 요구사항 (Non-Functional Requirements)

### 3.1 이식성 및 결합도 분리
*   **DIP 원칙 준수:** OpenAI SDK나 자체 vLLM HTTP API 라이브러리에 의존하지 않고, 추상화 계층(`LLMGateway`)을 거쳐 호출을 대행한다.
*   **환경 전파:** 테스트 환경(OpenAI)과 실제 운영 환경(자체 호스팅 vLLM) 변경 시, 소스 코드 수정 없이 오직 환경변수(.env) 값만 스위칭하여 기동한다.

### 3.2 테스트 가용성 (Testability)
*   실제 LLM API 호출을 동반한 유닛 테스트는 비용 및 API 호출량 한계(Rate limit)로 인해 모킹(Mocking)되어야 한다.
*   `pytest`를 사용해 프롬프트 생성, 입출력 구조화 직렬화/역직렬화 및 백엔드 설정 스위칭 로직의 코드 커버리지 95% 이상을 달성한다.

---

## 4. 제약 사항 (Constraints)
*   본 모듈은 Python 3.12 런타임 환경에서 동작한다.
*   의존성 관리는 `uv workspace`를 따르며, `.env`는 커밋되지 않도록 차단하고 `sample.env`를 동시에 현행화한다.
