# 03. 디렉토리 구조

> **대상 독자:** 새 프로젝트 디렉토리를 만들 나 자신 + Claude Code
> **용도:** 파일을 어디에 둘지. autoNote 가 지저분해진 원인을 반복하지 않는다
> **선행:** `02-아키텍처.md`

## 왜 이렇게 나누는가 — autoNote 의 실패에서

| autoNote 문제 | 실측 | 여기서의 대응 |
|---|---|---|
| 코드 집이 두 곳 (`program/` + `scripts/` 19개 파일) | 성격 다른 것이 한 곳에 섞임 | `packages/`(코드) / `cli/`(진입점) / `ops/`(운영) 3분할 |
| 문서가 다섯 곳 | 새 에이전트가 무엇을 먼저 읽을지 모름 | `docs/` 한 곳, `rules/` 아래 정본 하나 |
| `PYTHONPATH` 12곳 복붙 | **장애 2회** | 처음부터 패키지 + editable 설치 |
| 평평한 모듈명 (`notify`, `watchdog`) | 설치 시 PyPI 패키지와 충돌 | 처음부터 `rscope_*` 접두 패키지 |
| 런타임 파일이 `data/` 에 섞임 | 무엇이 git 대상인지 불분명 | `var/` 로 분리하고 통째 gitignore |
| 일회성 스크립트가 계속 누적 | 5개가 `scripts/` 에 쌓임 | `ops/migrations/` 로 격리, 끝나면 `archive/` |

> **실무 비유:** 인터페이스 시스템에서 송수신 모듈·공통 모듈·운영 스크립트를 한 디렉토리에 두면 뭘 배포해야 하는지 알 수 없게 된다. 배포 단위로 나눠야 한다.

## 이름 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| 패키지 | `rscope_` 접두 (충돌 방지) | `rscope_core`, `rscope_collect` |
| 앱 패키지 | 접두 없이 짧게 (진입점용) | `rscope` |
| 문서 | `번호-주제.md` (번호 = 읽는 순서) | `01-요구사항.md` |
| 설정 | `config/*.yaml` | `watchlist.yaml` |
| 런타임 | `var/` 아래 | `var/rscope.db` |

> `rscope` 는 "research scope" 의 가안이다. 착수 시 바꿔도 되지만 **접두를 붙인다는 원칙은 유지**할 것.

## `.gitattributes` (반드시 넣을 것)

```
* text=auto

# cmd.exe 는 LF 만 있는 배치 파일을 파싱하지 못한다.
# autoNote 에서 실제로 겪었다: LF 로 저장된 bat 이
# "'0' is not recognized as an internal or external command" 로 깨졌고,
# 스케줄러에서 매일 조용히 실패할 상황이었다.
*.bat text eol=crlf
*.cmd text eol=crlf

*.py  text eol=lf
*.md  text eol=lf
*.yaml text eol=lf
```

## 설치 (첫 세션에서 바로)

```powershell
cd <프로젝트루트>
python -m venv .venv                       # 권장: 전역 오염 방지
.venv\Scripts\activate

# uv 가 있으면 uv 사용, 없으면 pip
foreach ($m in @("packages/core","packages/ai","packages/collect","packages/filter","packages/extract","packages/render","packages/app")) {
    pip install -e $m --no-deps
}
pip install pydantic pydantic-settings pytest pytest-cov pyyaml
```

**설치 후 반드시 확인:**

```powershell
cd $env:TEMP
python -c "import rscope, rscope_core, rscope_collect; print('ok')"
```

무관한 디렉토리에서 import 가 되어야 `PYTHONPATH` 의존이 없다는 증거다.

> autoNote 는 가상환경 없이 전역에 설치했다. 문제는 없었지만 **가상환경을 쓰는 편이 낫다** — 다른 프로젝트와 패키지가 섞이지 않는다.

## 무엇을 어디에 둘지 헷갈릴 때

| 이런 파일 | 여기에 |
|---|---|
| 여러 패키지가 쓰는 공통 로직 | `packages/core/` |
| 특정 단계에만 쓰는 로직 | 그 단계 패키지 |
| 스케줄러가 실행하는 것 | `cli/` |
| 사람이 가끔 돌리는 도구 | `ops/tools/` |
| 한 번 돌리고 끝날 데이터 보정 | `ops/migrations/` |
| 이제 안 쓰지만 지우기 아까운 것 | `ops/archive/` |
| 값·목록·설정 | `config/` (코드에 박지 않는다) |
| 실행 중 생기는 것 | `var/` (gitignore) |
