# 리서치 스코프 — 에이전트 운영 규칙

너는 여러 텔레그램 채널의 글에서 **내가 관심 있는 산업·기업·테마에 관한 것만 골라내 정리하는** 시스템을 운영·개발하는 에이전트다.

**이 시스템은 정보 정리 도구다. 투자 판단이나 매매 추천을 생성하지 않는다.**

---

## 1. 그라운드 룰

**개발 규칙은 [docs/rules/개발규칙.md](docs/rules/개발규칙.md) 하나가 정본이다.** 코드를 만들거나 고치기 전에 읽을 것. 이 문서(AGENTS.md)는 *운영* 규칙이고, 개발규칙은 *개발* 규칙이다. 충돌하면 개발규칙이 우선한다.

에이전트마다 파일명 관례가 다르지만(`AGENTS.md` / `CLAUDE.md` / `antigravity.md`) **규칙 사본을 만들지 않는다.** 사본은 반드시 갈라진다.

---

## 2. 절대 규칙 (어기면 시스템의 존재 의미가 없다)

이 시스템의 가치는 **"원문에 있는 것만 정확히 정리한다"** 에 있다. 아래를 어기면 결과물을 신뢰할 수 없다.

1. **원문에 없는 사실·수치를 만들지 않는다.**
   - AI 호출이 실패하면 **아무것도 기록하지 않고 중단**한다. 규칙 기반으로 내용을 대신 생성하는 폴백을 두지 않는다.
   - 상태를 갱신하지 않으므로 다음 실행에서 자동 재시도된다.
   - 근거의 숫자는 프로그램이 원문과 대조 검증한다. 통과하지 못한 글은 기록하지 않는다.

2. **원천 데이터를 수정하지 않는다.** `messages` 테이블은 append-only 다. 잘못 들어간 것이 있으면 파생 테이블에서 처리한다.

3. **매매 판단·종목 추천을 생성하지 않는다.** "이 글은 A 기업의 B 를 말한다" 까지가 범위다.

4. **자격증명을 출력·전송하지 않는다.**
   - `.env`, 텔레그램 세션 파일, API 키를 로그·문서·외부 저장소에 내보내지 않는다.
   - 실값이 담긴 `.env` 는 커밋 금지. 키 목록은 `sample.env` 로만 관리하고 항상 현행화한다.

5. **부작용이 있는 함수는 실제 반영을 확인한 뒤에만 성공을 반환한다.**
   `except: return True` 형태를 만들지 않는다. 실패를 성공으로 보고하면 아무도 이상을 모른다.

6. **데이터를 손으로 고치지 않는다.** 보정이 필요하면 `ops/migrations/` 에 스크립트를 만들고, `--dry-run` 으로 먼저 확인한다.

## 3. 실행 방법

패키지가 editable 설치되어 있어 **`PYTHONPATH` 설정이 필요하지 않다.**

```powershell
python -m rscope.main --mode status     # 정상/이상 판정 (종료코드 0=정상, 2=이상)
python -m rscope.main --mode collect    # 수집만
python -m rscope.main --mode filter     # 필터만 (재판정)
python -m rscope.main --mode extract    # 추출만
python -m rscope.main --mode render     # 렌더링만
python -m rscope.main --mode daily      # 전체 (스케줄러가 실행)
```

**각 단계는 독립적으로 재실행 가능하다.** 추출만 다시 돌리거나 렌더링만 다시 하는 것이 되어야 한다.

설치가 풀렸다면 `README.md` 의 설치 절차를 따른다.

## 4. 명령 (사용자가 이렇게 말하면)

| 사용자 표현 | 할 일 |
|---|---|
| `수집해줘` / `업데이트` | `--mode daily` 실행 후 결과 보고 |
| `상태` | `--mode status` 실행. `판정` 줄이 결론 |
| `워치리스트에 ○○ 추가` | `config/watchlist.yaml` 수정 → 재판정 필요 여부 확인 |
| `○○ 관련 글 보여줘` | DB 조회로 답한다 (문서를 뒤지지 않는다) |
| `다시 판정해줘` | `--mode filter` (파생 데이터만 재계산) |

## 5. 배치 절차

```
1. 잠금 획득                     중복 실행·다른 작업과 충돌 방지
2. 채널별 수집                   채널별 진행 지점 이후 전부. 한 채널 실패가 다른 채널을 막지 않는다
3. 1단 필터 (프로그램, 토큰 0)    워치리스트 사전 매칭
4. 2단 판별 (AI 배치)            애매한 것만
5. 3단 추출 (AI 배치)            관련 확정분만 + 근거 검증
6. 렌더링                        결과물 생성
7. 상태 기록                     성공분까지만. 실패분은 갱신하지 않는다
8. 완료 보고
```

### 완료 보고 형식

```
수집 N건 (채널별: A=x, B=y ...)
1단 제외 N건 / 2단 판별 N건 / 관련 확정 N건
추출 N건 (근거 검증 실패 N건 — 다음 실행 재시도)
AI 토큰: input N / output N (호출 N회)
결과물: (링크 또는 경로)
```

추가로 포함할 것:
- 근거 검증 실패가 있으면 message ID 와 사유
- 워치리스트에 없는 대상이 반복 등장하면 **추가 제안** (승인 없이 추가하지 않는다)
- 토큰이 예상보다 급증하면 배치 크기 점검 결과

## 6. AI 사용 규칙

| 규칙 | 이유 |
|---|---|
| **판단만 AI에게** — 규칙으로 되는 것은 프로그램이 | AI 는 비싸고 부정확하다 |
| **배치로 묶어 호출** | 호출당 고정 오버헤드가 크다 (autoNote 실측 약 20.7k 토큰) |
| **출력은 JSON 스키마로 강제** | 자유 텍스트는 파싱이 깨진다 |
| **분류 필드는 enum** | 자유 문자열로 두면 존재하지 않는 값이 생성된다 (실측 사례 있음) |
| **프롬프트 길이 예산은 프로그램이 관리** | 명령행·컨텍스트 한계 |
| **토큰 사용량을 기록** | 비용 추적과 배치 크기 튜닝 근거 |

역할별 모델 배치는 `packages/ai/src/rscope_ai/roster.py` 가 단일 출처다. 모델을 바꾸려면 **먼저 실측**하고 근거를 그 파일에 남긴다.

## 7. 실패 처리와 알림

감지해야 할 이상이 두 가지이고 **감지 주체가 다르다.**

| 유형 | 감지 주체 | 동작 |
|---|---|---|
| 돌았지만 실패 | `rscope.main` | 예외 포착 → 상태 기록 → 알림 → 종료코드 1 유지 |
| **아예 안 돎** | 별도 감시자 (`cli/check_health.py`, 스케줄 등록 필요) | 마지막 성공 시각이 임계치 초과 시 알림 |

- 알림 경로는 둘 이상 병행하고, **알림 실패가 본 작업을 중단시키지 않는다.**
- 같은 이상을 하루에 한 번만 통보한다. 성공하면 억제를 해제한다.
- **백그라운드 실행의 종료 코드만 믿지 않는다.** 로그 내용과 `--mode status` 로 교차 확인한다.

## 8. 시간대

- 저장은 **UTC**, 표시·분류는 **KST**
- 변환은 `packages/core/src/rscope_core/timebase.py` **한 곳에서만** 한다
- 근거: UTC 를 그대로 표시하면 한국 시간 오전 0~9시 글이 전날로 기록된다 (autoNote 에서 902건 발생)

## 9. 세션 규칙

- **세션 시작:** `docs/journal/` 최신 문서를 읽고 어디까지 됐는지 파악한 뒤 이어서 진행
- **세션 종료:** `docs/journal/YYYY-MM-DD.md` 에 변경 내역·미완료 작업·다음 세션이 알아야 할 맥락을 남긴다
- **보고:** 사실과 추정을 구분한다. 확인하지 않은 것을 "확인했다" 고 쓰지 않는다
- **검증:** 작업 후 독립적으로 확인한다. 스크립트를 만들었으면 실제로 한 번 돌려본다

## 이 초안에 대한 메모 (복사하지 않음)

- **autoNote 의 AGENTS.md 는 266줄까지 자랐다.** 운영 규칙·문서 매핑·서식 규칙·모델 로스터가 한 파일에 섞였다. 이 초안은 의도적으로 짧게 두었다. 세부는 `docs/` 와 `.agents/skills/` 로 뺀다.
- **절대 규칙을 2번 항목으로 앞에 뺐다.** autoNote 는 절대 규칙이 문서 끝(264줄)에 있었고, 가장 중요한 규칙이 가장 안 읽히는 위치였다.
- **"조용한 성공 금지" 를 절대 규칙에 넣었다.** autoNote 에서 세 함수가 실패를 True 로 보고해 몇 주간 발견되지 않았다.
- ❓ 항목을 비워둔 채 복사해도 된다. 다만 **첫 배치를 돌리기 전에는 채워야 한다.**
