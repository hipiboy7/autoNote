## 3-1. 내일 본작업 — SQLite (사용자 요청)

> 사용자 결정 사항 (2026-08-10):
> **"먼저 SQLite 자체를 익히고, 그 다음 실제 구축."**
> 어느 프로젝트에 넣을지(새 다채널 프로젝트 / autoNote)는 **1~3단계를 해본 뒤에 정한다.**

### 시작 프롬프트 (내일 새 세션에 그대로 붙여넣기)

```
docs/journal/2026-08-10_작업요약.md 를 읽고 3-1절부터 진행해줘.
SQLite 를 처음 배우는 입장이니 1단계부터 순서대로 가고,
각 단계에서 내가 직접 확인할 수 있게 실제로 돌려서 결과를 보여줘.
```

### 진행 순서

| 단계 | 내용 | 산출물 |
|---|---|---|
| 1 | **SQLite 가 뭔가** — 서버 없는 DB, 파일 하나. Oracle/DB2 와 뭐가 다른가 | 설명 |
| 2 | **왜 이 프로젝트에 맞는가** — 단일 사용자·단일 프로세스, 백업 = 파일 복사 | 판단 근거 |
| 3 | **손으로 만져보기** — 테이블 만들고 넣고 조회, `UNIQUE` 제약이 중복을 막는 것 확인 | 실습 스크립트 |
| 4 | **실제 구축** — 대상 프로젝트를 정하고 `db.py` + 테스트 | 코드 |

3단계 실습은 `ops/archive/scratch/` 나 임시 디렉토리에서 한다. **운영 DB 를 실습에 쓰지 않는다.**

### 환경 확인 결과 (오늘 미리 점검함)

| 항목 | 결과 |
|---|---|
| `sqlite3` 파이썬 모듈 | 있음 (표준 라이브러리, 별도 설치 불필요) |
| SQLite 엔진 버전 | **3.50.4** |
| `UNIQUE` 제약 동작 | 확인됨 — 중복 insert 시 `IntegrityError` |
| `sqlite3.exe` CLI | 없음. 파이썬 모듈만으로 충분하므로 설치 불필요 |
| **`PRAGMA foreign_keys`** | **0 (꺼져 있음)** ← 아래 주의 |

> **첫 번째 함정 (Oracle 경험자가 반드시 걸리는 것).**
> SQLite 는 외래키 제약을 **기본적으로 무시한다.** 선언은 받아주지만 검사를 안 한다.
> 연결할 때마다 `PRAGMA foreign_keys = ON` 을 실행해야 한다.
> Oracle·DB2 는 FK 를 선언하면 항상 강제하므로, 이 차이를 모르면
> "제약을 걸었는데 왜 깨진 데이터가 들어오지?" 가 된다.
> `db.py` 를 만들 때 **연결 함수 한 곳에서** 켜는 것으로 처리한다.

### 스키마 초안 (이미 있음 — 4단계에서 씀)

`docs/nextpjt/02-아키텍처.md` 에 6개 테이블이 잡혀 있다.

| 테이블 | 역할 |
|---|---|
| `messages` | 원문. **append-only**, `UNIQUE` 로 중복 차단 |
| `channel_state` | 채널별 마지막 처리 지점 (지금의 `state.json` 역할) |
| `watchlist` | 관심 기업·산업·테마 + 별칭 |
| `relevance` | 관련성 판정 결과 (파생) |
| `extractions` | 추출된 논리·근거 (파생) |
| `ai_usage` | 토큰 사용량 |

**원천(`messages`)과 파생(`relevance`/`extractions`)을 나눈 이유:** 판정 로직을 바꿔도
원문을 다시 수집하지 않고 파생만 재계산하면 된다. autoNote 는 이 분리가 없어서
문서를 고치려면 원문보관에서 다시 읽어야 했다.

### 주의

- `.bat` 은 **CRLF 여야 한다.** LF 만 있으면 cmd 가 파싱을 못 한다 (`.gitattributes` 로 고정)
- 셸 heredoc 에 Windows 경로를 넣으면 **백슬래시가 이스케이프로 먹힌다.**
  실제로 `D:\autoNote` 가 `D:` + BEL(0x07) + `utoNote` 로 깨져 README 에 들어가 있었다.
  파일을 쓸 때는 heredoc 대신 편집 도구를 쓸 것
- 콘솔 한글 출력은 `PYTHONIOENCODING=utf-8` 없이는 `UnicodeEncodeError` 로 죽는다.
  **스크립트가 print 에서 죽어도 그 다음 줄은 실행된다** — 오늘 이것 때문에 토큰 사용량
  로그를 잃었다. 삭제는 반드시 `&&` 로 성공을 확인한 뒤에 붙일 것
