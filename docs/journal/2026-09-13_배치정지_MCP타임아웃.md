## 4. 고친 것

### ① MCP 응답 대기 상한 (docs·telegram 클라이언트)

`readline()` 을 별도 스레드에서 수행하고 큐로 받는다. `MCP_READ_TIMEOUT_SECONDS`
(기본 120초) 안에 못 받으면 `MCPReadTimeout` 을 올린다. Windows 파이프는 `select`
가 안 돼 스레드+큐 방식을 쓴다.

- Docs 클라이언트(장수 서버): 타임아웃 시 서버를 `kill` 하고 `process=None` 으로
  초기화 → 다음 호출이 `_ensure_connected` 로 새 서버를 띄운다. 매달린 읽기 스레드는
  EOF 를 받고 스스로 끝난다.
- Telegram 클라이언트(호출별 서버): 예외가 올라가면 기존 `finally` 가 서버를 종료한다.
- 스트림 닫힘·mock 소진은 EOF("") 로 취급해 기존 '스트림 닫힘' 경로를 그대로 탄다.

두 라이브러리에 같은 헬퍼를 각각 뒀다. 라이브러리 간 의존을 만들지 않기 위해서다.

### ② 쓰기 실패가 조용히 유실되던 경로 차단 ← **이게 더 위험했다**

타임아웃을 넣다가 발견했다. `append_text` 는 3회 재시도 후 실패를 **False 로
돌려주는데**, 배치 루프(`main.py`)는 `write_original_backup` / `write_research_report`
의 **반환값을 보지 않고 상태를 전진시킨다.** 즉 문서에 안 써졌는데 '처리됨' 으로
남는다 — 유실이 성공으로 위장되는 구조다. 타임아웃이 False 로 귀결되면 이 경로로
곧장 들어갔을 것이다.

writer 에 `DocsWriteError` 를 두고 `append_text` 가 False 면 예외를 올린다.
배치 루프는 예외를 받아 직전 성공 지점까지 상태를 저장하고 중단·알림한다(기존 경로).
백필은 건별 `continue` 라 그 건만 건너뛴다(기존 의미 유지). 테마 색 적용 실패는
장식이므로 예외로 올리지 않고 반환값으로만 남긴다.

### ③ sample.env 정리

- 8/26 에 코드에는 넣고 샘플에는 빠졌던 `BATCH_DUE_DEADLINE_HOUR` 추가
- 8/18 이후 어긋나 있던 워커 기본 모델 주석 갱신 (3.7-flash-high)

### ④ triage 폴백을 성공 알림에 실음 (사용자 요청)

9/4 처럼 triage 워커가 실패하면 후보 전원이 검증 없이 추출·기록되는데 알림이 없었다.
평소 성공 알림은 보내지 않는 원칙(매번 알리면 무시된다)은 유지하고, **폴백된 글이
있을 때만** ⚠️ 주의 알림을 보낸다.

- `ResearchTriage.fallback_ids` — classify() 마다 초기화, 기본값 처리된 id 를 기록.
  사유 문자열은 `REASON_FALLBACK` 상수로 통일 (문자열 비교로 세지 않는다).
- `BatchNotifier.notify_warning()` — `⚠️ autoNote 배치 주의` 헤더. 실패(🚨)·복구(✅)와 구분.
- `main.report_batch_success()` — 성공 뒤 알림 결정을 한 곳으로 모았다. 직전 실패면
  복구 알림, 폴백만 있으면 주의 알림, 둘이 겹치면 복구 알림 한 통에 폴백 내용을 싣는다.

  루프가 멈춘다.

- **밤에 도는 회수 실행은 사람이 없다.** 자동 회수가 편리하지만, 멈추면 아침까지 방치된다.
