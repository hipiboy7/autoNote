## 1. 배치 실패 근본 원인 (2건 동시)

1. **API 키가 실제 키가 아니었다.** `.env` 의 `REASONING_LLM_API_KEY`·`CHAT_LLM_API_KEY` 값이 문자열 `dummy-key`(9자). 모든 OpenAI 호출이 401. 실제 키가 들어간 적이 없다.
2. **agy 폴백은 처음부터 성공 불가 구조였다.** OpenAI 모델 ID(`o4-mini`)를 그대로 agy `--model` 로 넘겼다. `agy models` 목록에 없는 이름이라 exit 1.
   - 검증: `agy --model gemini-3.5-flash-medium --print "..."` → 정상 응답. **agy 자체는 인증·동작 모두 정상. 모델명만 틀렸다.**

어제까지는 제거된 창작 폴백이 그 자리를 메워 exit 0 으로 끝났고, 스케줄러에도 성공으로 기록됐다. **정상 동작한 것이 아니라 실패가 은폐돼 있었다.**

## 2. agy 능력 실측 (설계 근거)

`--json-schema` 는 `--output-format json` 과 함께만 사용 가능. 응답 엔벨로프에 `structured_output`·`usage`·`num_turns` 가 있다. **enum 은 실제로 강제된다** (자유 문자열일 때 존재하지 않는 테마 `'금지'` 가 생성됨 → enum 적용 후 전 모델 `'금리'` 정확).

## 3. 구조 (AGENTS.md 참조)

- **agy 에는 subagent 정의 기능이 없다.** 커스터마이징 타입은 Rules/Skills/Plugins/Hooks/MCP 뿐이고 `agy agents` 는 비어 있다. 따라서 "서브에이전트" = 모델+추론강도+역할프롬프트+스키마 조합의 1회성 워커. 정의는 `program/src/worker_roster.py` 단일 출처.
- 로스터: `triage`(15건/호출) / `extract`(4건) / `review`(주1회) / `repair`(4건). `AGY_WORKER_<ROLE>_*` 로 오버라이드.
