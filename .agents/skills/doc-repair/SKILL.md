# 문서 복구 런북

## 무엇이 왜 오염되었는가

LLM API 키가 `dummy-key` 인 상태로 배치가 돌던 기간(2026-07 ~ 2026-08-04), 지금은 제거된 규칙 기반 폴백이 원문과 무관한 고정 문구를 생성해 문서에 기록했다. 배치는 exit 0 으로 끝나 실패가 드러나지 않았다.

식별 표지 (`analyzer.grounding.FABRICATION_MARKERS`):

- `분야 전략적 판단을 도출함`
- `관련 저자 주요 결론 요약`
- `시장 변동성 및 거시경제 지표 변화에 따른 잠재적 위험 관찰 필요`
- `가설이 유지되기 위해 추적해야 할 핵심 지표는 무엇인가`
- `본문 내 주요 수치 데이터 및 팩트 참고`
- `LTA 비중이 70%`, `유가(100달러 선)`

## 왜 제자리 치환이 아니라 새 문서인가

창작 문구는 199개 블록에 **완전히 동일한 문자열**로 들어가 있다. Google Docs `replaceAllText` 는 일치하는 모든 곳을 바꾸므로 제자리 치환을 강행하면 무관한 블록까지 오염된다. 그래서 새 문서로 재구성하고 매핑을 교체한다. 기존 문서는 지우지 않고 아카이브로 남는다.

## 실행

```powershell
cd D:\autoNote
$env:PYTHONPATH="program/src;program/libs/agy-gateway/src;program/libs/google-docs-client/src;program/libs/telegram-client/src;program/libs/llm-gateway/src;program/services/analyzer/src;program/services/collector/src;program/services/merger/src;program/services/reviewer/src;program/services/writer/src"
$env:PYTHONIOENCODING="utf-8"

# 1) 먼저 반드시 집계만 (문서를 만들지 않는다)
python program/src/main.py --mode repair --dry-run

# 2) 문서 하나씩 복구 (권장 — 결과를 눈으로 확인하면서 진행)
python program/src/main.py --mode repair --doc 금리
python program/src/main.py --mode repair --doc 방산·방위산업

# 3) 전체 복구 (오래 걸린다)
python program/src/main.py --mode repair --doc all
```

**작은 문서(금리 16블록, 방산 6블록)부터 하고 결과를 확인한 뒤 큰 문서로 넘어갈 것.** 반도체사이클 199블록은 약 50회 호출 · 1.2M 토큰 · 30분 이상 걸린다.

## 동작 원리

1. 대상 문서를 블록 단위로 파싱하고 창작 표지가 있는 블록을 찾는다.
2. `00_원문보관` 문서들에서 식별자 → 원문 본문 맵을 만든다.
3. 오염 블록의 원문만 `repair` 워커로 재분석한다. **근거 검증(숫자 대조)을 통과해야 채택된다.**
4. 새 문서를 만들어 **원래 순서대로** 재조립한다.
   - 정상 블록: 원문 그대로 복사 (재분석하지 않는다)
   - 오염 블록: 재생성한 내용으로 교체
   - **사용자 `▶ 💭 내 생각` 은 오염 블록이라도 그대로 보존한다**
   - 원문을 못 찾거나 재분석 실패한 블록: 기존 내용 그대로 보존하고 실패 목록에 보고
5. 세피아 테마를 적용하고 `state.json` 의 `doc_overrides` 에 새 문서 ID 를 등록한다. 다음 배치부터 새 문서에 기록된다.

## 복구 후 할 일

1. 새 문서를 열어 내용을 확인한다. 특히 재생성된 블록의 근거가 원문과 맞는지 표본 검사.
2. **`AGENTS.md` 의 문서 매핑표를 새 문서 ID 로 갱신한다.**
3. 기존 문서 제목에 `(구버전-창작오염)` 을 붙여 혼동을 막는다.
4. 실패 목록이 있으면 사용자에게 보고한다. 원문보관에 원문이 없는 블록은 자동 복구가 불가능하다.
5. `working_docs/` 에 복구 이력을 남긴다 (문서별 재생성 건수, 새 문서 ID, 실패 목록).

## 주의

- `doc_overrides` 를 손으로 지우면 매핑이 원래 문서로 돌아간다. 되돌릴 때만 사용할 것.
- 복구 중 배치가 돌면 잠금이 충돌한다 (같은 `batch.lock` 을 쓴다). 08:50 스케줄과 겹치지 않게 실행할 것.
